# 01. 要件定義

## 1. 背景と目的

AI エージェント（Claude Code / Cursor / Kiro など MCP クライアント）が MySQL に関わる作業をする際、
学習データの記憶に頼ると以下の問題が起こる。

- バージョン差分の取り違え（例: 8.0 では使えたが 8.4 で削除されたオプションを提案する）
- システム変数のデフォルト値・スコープ・動的変更可否の誤り
- 構文の細部（`JSON_TABLE`、ウィンドウ関数、CTE、`ALTER TABLE ... ALGORITHM=INSTANT` の制約など）の誤り
- 学習データのカットオフ以降のリリース（例: 9.7 LTS、26.x 系）を知らない

本プロジェクトは [AWS Documentation MCP Server](https://awslabs.github.io/mcp/servers/aws-documentation-mcp-server) の
MySQL 版として、**MySQL 公式ドキュメント（dev.mysql.com/doc）を AI エージェントが検索・参照できる MCP サーバー**を提供し、
公式ドキュメントに根拠を持つ正確な出力（出典 URL 付き）を可能にする。

## 2. 想定ユースケース

| # | ユースケース | エージェントの動き（例） |
|---|---|---|
| UC-1 | クエリ作成・レビュー | `search_documentation("window function frame clause", version="8.4")` → `read_documentation(...)` で構文を確認してからクエリを書く |
| UC-2 | バージョンアップ時の変更点調査 | `get_release_notes(from_version="8.0.36", to_version="8.4.6", categories=["deprecation_removal", "functionality_changed"])` で差分を列挙し、`get_upgrade_guide` で公式の移行手順を確認 |
| UC-3 | 設定値の確認 | `lookup_reference("innodb_buffer_pool_size", kind="system_variable", version="8.4")` でデフォルト値・範囲・動的可否を取得 |
| UC-4 | エラー調査 | `lookup_reference("1213", kind="error")` でエラーコードの意味を確認 |
| UC-5 | 機能の存在確認 | 同一ページを複数バージョンで読み比べ（URL のバージョン部分を差し替え）、導入/削除バージョンを確認 |

## 3. 機能要件

### 必須（MVP）

- **FR-1 検索**: キーワードで公式ドキュメントを検索し、タイトル・URL・セクション番号・抜粋を返す。バージョン指定可能。
- **FR-2 ページ読み取り**: dev.mysql.com のドキュメント URL を取得し Markdown に変換して返す。長いページは文字数ベースでページネーション。
- **FR-3 セクション読み取り**: 巨大ページ（`server-system-variables.html` 等）から指定見出し/アンカーの部分のみ返す。
- **FR-4 リリースノート取得**: 指定バージョン範囲のリリースノートをカテゴリ（非推奨・削除 / 機能追加・変更 / 不具合修正 等）とキーワードで絞って返す。
- **FR-5 バージョン一覧**: 参照可能なマニュアル・リリースノートのバージョン一覧（LTS / Innovation の別を含む）を返す。

### 推奨（MVP 後）

- **FR-6 リファレンス項目のピンポイント参照**: システム変数・ステータス変数・コマンドラインオプション・関数・SQL 文・エラーコードを名前で引く。
- **FR-7 アップグレードガイド**: 「What Is New in MySQL X」「Upgrading MySQL」系ページへの導線。
- **FR-8 目次ブラウズ**: 検索でヒットしない場合に章立て（TOC）をたどれる（AWS 版の `recommend` の代替）。
- **FR-9 大きな表の検索**: オプション/変数一覧表など巨大な表から行を絞り込む（AWS 版の `search_table` 相当）。

## 4. 非機能要件

| 区分 | 要件 |
|---|---|
| 正確性 | 返す内容は必ず公式ドキュメント由来とし、出典 URL とバージョンを出力に含める。要約・加工はサーバー側で行わない（エージェントに委ねる）。 |
| 性能 | 検索はローカルインデックスで 1 秒以内。ページ取得はキャッシュヒット時 100ms 以内、ミス時はネットワーク依存（タイムアウト 30 秒）。 |
| コンテキスト効率 | 1 レスポンスの既定上限は 10,000 文字程度。ナビゲーション・フッター等の不要要素は除去する。 |
| 配布容易性 | `uvx mysql-documentation-mcp` のワンライナーで起動できる（AWS 版と同様）。追加のデータベースやサーバーは不要。 |
| オフライン耐性 | 一度インデックス/キャッシュを作成すれば、検索と既読ページ参照はオフラインでも動作する。 |
| サイトへの配慮 | dev.mysql.com へのアクセスはレート制限・キャッシュ・識別可能な User-Agent で最小化する。 |
| セキュリティ | 取得先は許可リストのドメインのみ（SSRF 防止）。リダイレクト先も検証する。 |
| ライセンス | MySQL ドキュメント本体（Oracle 著作物）をパッケージやリポジトリに同梱・再配布しない。利用者の環境で取得・キャッシュする。 |

## 5. スコープ外

- MySQL サーバーへの接続・クエリ実行（本サーバーはドキュメント参照専用）
- ドキュメント内容の翻訳・要約（エージェント側の責務）
- MariaDB / Percona / Aurora MySQL 等の派生製品ドキュメント（将来の拡張候補）
- 埋め込みベクトルによるセマンティック検索（MVP では全文検索。将来の拡張候補）

## 6. 対象ドキュメント

MVP の対象は以下の 2 種類。その他（MySQL Shell、Connector/J、Router、NDB Cluster 等）は将来の拡張で `doc_set` として追加する。

| doc_set | URL パターン | 用途 |
|---|---|---|
| `refman` | `https://dev.mysql.com/doc/refman/{version}/en/{page}.html` | リファレンスマニュアル本体 |
| `relnotes` | `https://dev.mysql.com/doc/relnotes/mysql/{series}/en/news-{x}-{y}-{z}.html` | サーバーのリリースノート |

対象バージョン: 5.7（EOL だが移行元として需要あり）/ 8.0 / 8.4 LTS / 9.x（9.7 LTS 含む）/ 26.x 以降（カレンダーバージョニング）。
バージョン一覧はハードコードせず動的に取得する（→ [02_design.md](02_design.md) §5.4）。

> 補足: MySQL は 9.7 LTS（2026-04）を最後に連番バージョンを終え、以降は `YY.M` 形式（例: 26.7）になったと公式マニュアルに記載がある。
> バージョン文字列のパース・比較はこの両方に対応する必要がある。
